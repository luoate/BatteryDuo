# Battery · ATK A9 Ultimate + 狼蛛 A7 Pro 双设备电量托盘

> Windows 11 · 2.4GHz USB 接收器 · 双托盘图标 · Python / PySide6 / hidapi  
> 本说明对应 `battery_双电量托盘_主动查询_v1_1.zip` 中的项目，而不是早期 v0.x 测试工具。

这个项目在 Windows 系统托盘中**同时显示两台无线设备的电量**：

- **鼠标图标**：ATK A9 Ultimate 鼠标的电量；
- **耳机图标**：狼蛛 / AULA A7 Pro 耳机的电量和充电状态。

每台设备使用独立的 HID 驱动、工作线程和托盘图标。电量来自 **USB 接收器的设备协议**，不是 Windows 蓝牙电量 API，也不是通过使用时间估算。

> **验证范围**：以下 VID/PID、HID 接口以及狼蛛的响应字段来自本项目开发过程中的实际设备枚举、描述符、抓包与用户测试。ATK 的电量查询主要依据开源驱动实现和本机接口枚举；尚不能将离线单元测试等同于两台设备的长期实机稳定性测试。狼蛛主动查询已有一次成功的发送与响应测试，但持续自动轮询仍建议实测确认。

## 一、功能和运行方式

| 功能 | ATK A9 Ultimate（鼠标） | 狼蛛 A7 Pro（耳机） |
| --- | --- | --- |
| 连接方式 | 2.4GHz USB 接收器 | 2.4GHz USB 接收器 |
| 托盘显示 | 鼠标 SVG + 底部电量条 | 耳机 SVG + 底部电量条 |
| 获取电量 | 定时发送 HID 查询，读取响应 | 被动接收事件；可手动启用定时 HID 主动查询 |
| 默认刷新方式 | 每 60 秒查询一次 | 持续监听设备主动上报 |
| 可选主动查询 | 已作为常规功能使用 | **默认关闭**；启用后自动查询间隔不小于 60 秒 |
| 充电显示 | 返回“有线标志”，**不直接等同于正在充电** | 状态 `0x02` = 未充电；`0x03` = 正在充电 |
| 异常与历史读数 | 无法读取时保留上次有效值并标记异常 | 无新数据超过 30 分钟会灰显；重新启动可读取本地历史缓存 |
| 低电量提醒 | 支持 | 支持；耳机正在充电时不提醒 |

两只托盘图标会同时存在（即使只有一只接收器插入）。托盘使用放大的设备轮廓，底部电量条随剩余电量变化，不再绘制数字。悬浮提示或右键菜单中可以查看准确百分比；右键菜单还会显示最近更新时间。

底部电量条按百分比显示颜色：≤10% 红色、11%–25% 橙色、>25% 绿色；过期/异常数据显示为灰色。耳机图标右上角的蓝点表示正在充电。鼠标轮廓为青色，耳机轮廓为紫色；无有效电量或历史数据时轮廓灰显。图标使用根目录的 `鼠标滚轮.svg` 和 `耳机.svg`，打包时会一并嵌入 EXE。右键菜单以设备状态卡片展示电量条、更新时间和状态，操作选项收纳到“设置”子菜单。

## 二、两台设备如何读取电量

软件的流程如下：

```text
                  Windows 11 托盘程序（atk_tray.py）
                                   |
                      +------------+------------+
                      |                         |
                 鼠标：ATK                   耳机：狼蛛
                      |                         |
          独立 QThread + hidapi      独立 QThread + hidapi
                      |                         |
            373B:11D9 接收器          38A6:0001 接收器
                FF02:0002                   FF90:0001
                      |                         |
             发送 17 字节查询         被动监听 64 字节报告
                      |                  （或启用主动查询）
                解析电量值                      |
                      |                  解析电量及充电状态
                      +------------+------------+
                                   |
                       更新两个 QSystemTrayIcon
```

程序通过 `hid.enumerate(VID, PID)` 找到目标 HID 集合，再用设备返回的 `path` 精确打开接口，避免误操作同一接收器下的通用鼠标、键盘、电话或音频控制接口。

**注意：** 插入 USB 接收器只表示接收器在线，不必然意味着无线鼠标/耳机本体已经连接，更不能将“接收器在线”当作电量有效。

## 三、ATK A9 Ultimate：主动查询协议

### 3.1 设备定位

| 字段 | 数值 |
| --- | --- |
| 型号 | ATK A9 Ultimate，2.4GHz |
| Vendor ID | `0x373B` |
| Product ID | `0x11D9` |
| Usage Page | `0xFF02` |
| Usage | `0x0002` |
| Interface | `1` |
| HID Report ID | `0x08` |
| 读写报告长度 | `17` 字节（含 Report ID） |

本机 HID 枚举已确认 `373B:11D9 / FF02:0002 / Interface 1`。协议实现参考 [Fan4Metal/mouse_tray 的 Nordic52 驱动](https://github.com/Fan4Metal/mouse_tray/blob/master/mouse_tray/drivers/chipset/nordic52.py)，并沿用原 `battery.zip` 项目的 Python 组织方式。

### 3.2 查询请求

```text
08 04 00 00 00 00 00 00 00 00 00 00 00 00 00 00 49
```

共 17 字节，其构成为：

- `[0]`：`0x08`，Report ID；
- `[1]`：`0x04`，电量查询命令；
- `[2..15]`：14 个 `0x00`；
- `[16]`：`0x49`，用于满足报文校验规则；
- 校验要求：`sum(request) % 256 == 0x55`。

程序执行 `hid.device().open_path(...)` → `write(QUERY)` → 短暂等待 → `read(17, timeout_ms=...)` → 关闭句柄。鼠标默认每 60 秒查询一次；读取超时不会自动生成假电量。

### 3.3 响应解析

一条参考响应如下（**开源协议示例，不是当前时刻的实测读数**）：

```text
08 04 00 00 00 02 23 00 0E 94 00 00 00 00 00 00 82
                  ^^    ^^^^^
                  35%   3732 mV
```

代码 `atk_a9_battery.py` 中：

| Python 字节索引 | 含义 | 说明 |
| --- | --- | --- |
| `data[0]` | Report ID | 必须是 `0x08` |
| `data[1]` | 查询命令 | 必须是 `0x04` |
| `data[6]` | 电量百分比 | `0–100` 的整数；例：`0x23` = 35 |
| `data[7]` | 有线标志 | **不可靠地代表正在充电** |
| `data[8:10]` | 电池电压 | 大端序：`(data[8] << 8) | data[9]`，单位 mV |

程序还验证：报告长度必须为 17 字节、报文前缀必须正确、`sum(response) % 256 == 0x55`、电量不得超过 100。电压仅在 `2500–5000 mV` 之间时作为参考值展示。

### 3.4 数据可靠性

鼠标电量来自设备报告，不是用电压自行估算。鼠标休眠、接收器被拔出或 ATK HUB 同时占用通道可能导致读取失败；界面保留上一条有效读数并将其标为非最新数据。**有线标志不能替代独立的充电状态判定。**

## 四、狼蛛 A7 Pro：主动查询 + 被动上报

### 4.1 设备定位

| 字段 | 数值 |
| --- | --- |
| 型号 | AULA / 狼蛛 A7 Pro，2.4GHz |
| USB 芯片厂商名称 | C-Media Electronics Inc |
| Vendor ID | `0x38A6` |
| Product ID | `0x0001` |
| Interface | `0` |
| Usage Page | `0xFF90` |
| Usage | `0x0001` |
| Report ID | `0x55` |
| Input / Output Report | Windows 实测能力均为 **64 字节**（含 Report ID） |

早期 HID 描述符重建工具只还原了 `FF90` 的 Input Report；后来 Windows `HIDP_CAPS` 实测报告 Input/Output 都是 64 字节，且一次真实 `hid.write` 成功写入了 64 字节。这一差异说明**仅靠重建后的 Report Descriptor 不足以判定该设备是否允许 Output Report**。

### 4.2 被动上报：不发查询也能收到电量

打开 `FF90` 的 HID 设备后，程序调用 `read(64, timeout_ms=...)` 接收无线接收器传来的 Input Report。

在用户 USB 抓包中发现的有效事件：

```text
55 65 50 02 00 00 ... 00
|  |  |  |
|  |  |  +-- 0x02：未充电
|  |  +----- 0x50 = 十进制 80，即 80% 电量
|  +-------- 电池消息标记 0x65
+----------- Report ID 0x55
```

经用户进一步实机核实：

| 电池消息的字段 | 含义 |
| --- | --- |
| `data[0] == 0x55` | Report ID |
| `data[1] == 0x65` | 电池状态消息标记 |
| `data[2]` | 电量百分比，直接读取整数 `0–100` |
| `data[3] == 0x02` | 未充电 |
| `data[3] == 0x03` | 正在充电 |

例如：`55 65 50 03` 表示 80% 且正在充电。

**特殊情况**：抓包还发现 `55 65 00 1A`，对应一次耳机关闭/断开事件。`aula_a7pro_battery.py` 会识别并排除它，**不会显示为 0% 电量**。如果状态字节未知或百分比越界，也会拒绝解析，以防虚假显示。真正的 0% 只有在状态字节属于合法的 `0x02/0x03` 时才会被当作电量值。

### 4.3 主动查询：不必只等耳机上报

虽然耳机可以自发上报电池状态，但如果长期没有事件，托盘数值可能无法及时更新。基于 [rafagfran/mchose-v9-pro-battery-tray](https://github.com/rafagfran/mchose-v9-pro-battery-tray) 的研究，项目针对 **狼蛛 A7 Pro 自己的 VID/PID 和 FF90 接口**验证了如下 64 字节 HID Output Report：

```text
55 65 01 00 00 00 00 00 ... 00
\_______/ \___________________/
  3 字节     后续 61 字节均为 00
```

其 Python 代码定义为：

```python
QUERY = bytes([0x55, 0x65, 0x01] + [0x00] * 61)
```

在用户 Windows 实机的**单次独立测试**中：

1. 接收器 `38A6:0001 / FF90:0001` 的 HID 能力为 `Input=64`、`Output=64`、`Feature=0`；
2. 发送上述查询，`hid.write(...)` 成功写入 **64 字节**；
3. 查询前未收到有效报告；
4. 查询后收到 `55 65 50 02 ...`，即 **80%、未充电**。

这为“查询会触发电量返回”提供了**很强的实际依据**。但单次实验尚无法完全排除恰好收到自主上报的情况，所以 v1.1 将定时主动查询标记为 **实验性功能，默认关闭**。

在任意一个托盘图标上右键，勾选：

> **设置 → 耳机主动查询（实验性，间隔≥60秒）**

启用后：

- 程序继续监听普通 Input Report；
- 到期时用**同一个 FF90 HID 句柄**发送固定 `QUERY`，随后继续等待输入响应，避免另开一个句柄造成竞争；
- 自动查询最短间隔 **60 秒**，用户设置的间隔若小于 60 秒，耳机仍按 60 秒执行；
- “立即查询耳机电量”仅在启用主动查询后可用，手动请求的最短间隔 **10 秒**；
- 关闭主动查询后，不再主动发送请求，但仍然监听被动上报；
- 若写入失败或未返回有效数据，不会凭空生成百分比。

**注意**：这里所谓“主动查询”是**向接收器发送 HID Output Report**（技术上属于写入 USB 请求），其用途是读取电量；它不是固件烧录、EQ 更改或其他配置命令。不要把此命令移植到未知耳机型号上盲试。自动轮询的长期稳定性、断线恢复和对其他固件版本的兼容性仍需实际验证。

### 4.4 参考开源项目与本机实测的区别

[MCHOSE V9 Pro Battery Tray](https://github.com/rafagfran/mchose-v9-pro-battery-tray) 是**另一款耳机**的开源项目，其接收器 `VID:PID=291D:385D`，**并不是狼蛛 A7 Pro (`38A6:0001`)**。该项目验证了 `FF90`、`0x55` 和 `55 65 01...` 的查询形式，并从响应第三个字节得到电量。但该仓库**没有确认狼蛛 `0x02/0x03` 的充电语义**；充电状态对应关系来自本项目使用的狼蛛 A7 Pro 的独立实测。

本项目不会因为两款耳机使用相似芯片和报文，就自动认为它们所有控制指令兼容。

## 五、界面刷新、缓存及异常处理

### 5.1 两个图标为什么可以同时刷新？

- `atk_tray.py` 使用 **PySide6 / QSystemTrayIcon** 创建鼠标和耳机两个独立托盘图标；
- 两台设备各有一个 `BatteryReader(QThread)`；
- 鼠标线程周期性执行 `atk_a9_battery.py` 的查询；
- 耳机线程持续读取 `aula_a7pro_battery.py` 的输入报告，需要时穿插主动查询；
- 读取线程通过 Qt 信号把状态发送到界面线程，不让 USB 读取超时阻塞托盘菜单。

### 5.2 超时、未知电量和历史数据

- 还没有任何有效值：显示灰色设备轮廓和空电量条，菜单百分比为 `--%`；
- 读取错误：保留最近成功的电量，但显示为灰色，并在菜单中标注异常；
- 耳机超过 **30 分钟**没有新的有效上报：将读数灰显为历史数据；
- 最近的耳机电量会存入本地缓存；重启时如读到可用缓存，也**只能显示历史数据**，不能当作当前实时电量；
- 无新上报 ≠ 电量不变；接收器在线 ≠ 耳机一定在线。

### 5.3 低电量提醒及设置

默认提醒阈值为 **20%**；右键菜单可以调整阈值、开启/关闭提醒、修改刷新间隔、设置登录时自动启动。

- 鼠标低电量可提醒；
- 耳机低电量且**未充电**时可提醒；
- 耳机正在充电时不触发低电量提醒；
- 同一低电量阶段避免反复弹窗。

配置存放在：

```text
%APPDATA%\ATK A9 Tray\config.json
```

耳机主动查询开关由 `headset_active_poll` 字段记录，默认 `false`。程序的日志调试模式写入：

```text
%APPDATA%\ATK A9 Tray\tray.log
```

## 六、安装、启动与调试

**环境**：Windows 11、Python 3（建议 3.10+）、ATK A9 Ultimate 的 2.4GHz 接收器、狼蛛 A7 Pro 的 2.4GHz 接收器。

### 快速开始

将该 `README.md` 放在 v1.1 项目根目录后：

1. 退出以前运行的旧版托盘监控和可能占用 HID 通道的设备控制面板。
2. 双击 `安装依赖.bat`，安装 `hidapi` 和 `PySide6`。
3. 双击 `启动托盘.bat`，软件会调用 `pythonw` 后台启动。
4. 在 Windows 11 任务栏通知区域寻找 **鼠标、耳机两个图标**；若被折叠，在 `^` 隐藏图标中查看，或于“设置 → 个性化 → 任务栏 → 其他系统托盘图标”开启显示。
5. 如要让耳机定时主动查询，右键任意设备图标，在“设置”中勾选上述**实验性**选项。

也可在终端手动执行：

```powershell
python -m pip install hidapi PySide6
python atk_tray.py --debug
```

### 单独检查鼠标电量

```powershell
python atk_a9_battery.py --debug
```

检查鼠标 HID 请求、返回数据和校验信息。鼠标本体如果休眠，建议先移动鼠标唤醒；如果报接口占用，先退出 ATK HUB。

### 单独检查耳机电量

只监听被动上报：

```powershell
python aula_a7pro_battery.py --debug --seconds 30
```

确认接受实验性单次主动查询后，在**完全退出托盘程序**的情况下，双击 `验证耳机主动查询.bat`，或执行：

```powershell
python aula_a7pro_battery.py --active-query --seconds 10 --debug
```

该方式在最多 10 秒的观察时间内尝试读取；它并不保证每次都成功。**不要同时运行多个程序竞争访问 FF90。**

### 运行离线协议测试

```powershell
python -m unittest test_protocol -v
```

离线测试验证解析器、报文格式和部分模拟读取流程，不代表 USB 接收器的长期稳定性已经验证。

### 打包为 EXE

双击 `build_exe.bat`，由 PyInstaller 在本机尝试生成：

```text
dist\ATK-AULA-DualBattery.exe
```

打包脚本 `build_exe.py` 会隔离 DLL 搜索路径，避免将 Poppler、Conda 等工具的同名 ICU DLL 错收进 EXE。生成后自动运行 EXE 的离线 UI 自检，验证 Qt 加载、SVG 和菜单渲染；结果保存在 `build/packaged-ui-check.json`，自检不访问 HID 设备。

该版本提供的是 Python 源码，**不是已签名的 Windows 安装包**。旧版如已设置登录时自启，应在新版菜单里关闭后重新开启，使注册表启动路径更新。

## 九、兼容性、安全边界与验证说明

- **仅针对明确识别的型号和 HID 集合**。不要只凭厂家名称相似就向别的设备发送请求。
- 耳机 `55 65 01 ...` 是**有输出操作的查询指令**，不是纯被动监听；尽管它已在当前 A7 Pro 接收器上单次返回有效电量，仍需要用户自行决定是否开启定时轮询。
- 软件没有设计固件烧写、EQ 调整、DPI 修改或未知 Report ID 扫描功能。
- 更新/异常时保留历史值并标注，不用模拟数字伪造实时电量。
- 系统托盘小图标在不同 DPI、Windows 缩放、主题与任务栏设置下可能显示略有差异。
- 如果遇到耳机声音中断、接口访问冲突、USB 异常，请先关闭主动查询与托盘程序，再重新插拔接收器；不要反复连续发送未知命令。
- 本项目是第三方独立工具，与 ATK、AULA / 狼蛛、C-Media 和 MCHOSE 厂商没有关联、授权或背书。

---

**一句话总结：** 鼠标图标通过 ATK 的 17 字节 HID 查询获取鼠标电量；耳机图标通过狼蛛 A7 Pro 的 `FF90` 64 字节 HID 电量报告获取耳机电量，可选择主动发送 `55 65 01 ...` 查询，也能接收设备自发上报；两个驱动独立工作，并分别更新系统托盘电量条。
